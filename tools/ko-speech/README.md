# ko-speech — `Pick` 밖에서 새는 외국어 리터럴을 고정한다

`tools/assemble`이 **표식으로 갈라지는 자리**를 옮긴다면, 이쪽은 그 표식 밖을 묻는다 — **독일어·영어가 왜 이 자리에 맨몸으로 있나.**

## 왜 생겼나

사용자가 인게임에서 `불멸대 막사 방향 통로, Übergang, 54미터, 왼쪽`을 들었다. 그 `Übergang`은 소스에 맨 리터럴로 박혀 있어서 대장에도 안 들어갔고, **당시 검사 넷이 하나도 못 잡았다.**

`Loc.Pick`은 한국어가 없으면 영어로 떨어지되 그 자리를 로그에 적는다(`replace/FF14Accessibility/Loc.cs:154-160`). 그런데 애초에 `Pick`을 안 거치면 그 폴백조차 없다 — 독일어가 그대로 나간다.

**조립의 숫자로는 안 보인다.** `tools/assemble`이 보는 것은 `scanner.MARKERS`의 표식과 `Pick(`뿐이라, 둘 다 없이 맨 리터럴로 앉은 자리는 `미적용`에도 `못 읽음`에도 안 나타난다. 조립 보고가 전부 0이어도 이 부류는 그 숫자 밖에 있다.

## 판정 대상은 조립 산출물이다

`tools/loc-check`가 `build/Installer`를 보는 것과 같은 까닭이다. 플러그인 소스가 `upstream/`·`kr/`·`replace/` 셋에 흩어져 있고, 조립이 중첩 삼항을 펴고 `Pick`을 써 넣은 **뒤**의 트리가 실제로 나갈 것이다.

**조립을 안 돌렸으면 1을 돌려주고 멈춘다.** 소스가 없으면 0건이 나오는데, 그 침묵은 "새는 자리가 없다"와 구분이 안 된다.

    uv run python tools/assemble/assemble.py
    uv run python tools/ko-speech/ko_speech.py

골든을 갱신할 때는 `--write`를 붙인다.

    uv run python tools/ko-speech/ko_speech.py --write

pytest가 같이 돌린다 — `uv run python -m pytest tools/ko-speech`.

## 무엇을 하나

판정을 **셋으로 나눈다.** 한 규칙으로 묶으면 오탐이 섞여 다 죽는다.

| 갈래 | 무엇을 보나 | 왜 나눴나 |
|------|-------------|-----------|
| `umlaut` | `[äöüßÄÖÜ]`를 가진 리터럴이 `Pick`/삼항 밖에 있다 | 이 문자는 한국어에도 명령어에도 안 나와서 문자셋만으로 갈린다 |
| `sibling` | `switch` 가지나 배열 초기화에서 형제가 `Pick`인데 자기만 맨 리터럴이다 | `Aethernet`·`Ort`·`FATEs`는 움라우트가 없어 이 규칙으로만 잡힌다 |
| `speech` | 발화 싱크(`Speak`·`SpeakInterrupt`·`Braille`)의 인자인데 한글이 없다 | 움라우트도 형제도 없는 한 줄짜리 새 파일이 앞 둘을 통째로 빠져나간다 |

지금 몇 건인지는 여기 적지 않는다. 도구가 돌 때마다 세어서 말한다 — 손으로 옮겨 적은 숫자는 낡는다.

## 오탐 셋 — 전부 계산으로 갈린다

1. **비교 키** — `p.TypeLabel is "Ätheryt" or "Aethernet"`. 발화가 아니라 식별자다. 리터럴만 바꾸면 에테라이트 분류가 예외도 로그도 없이 죽는다
2. **로그** — `_log.Info($"[Nav] ...")`. 감싸는 호출을 바깥으로 훑어서, 한 겹 더 들어가 있어도 잡는다
3. **파서가 모양을 못 읽은 언어 분기** — `AccessibilityStrings.cs`의 중첩 삼항. 조립도 못 읽어 `못 읽음`으로 세는 자리라, 여기서 다시 세면 상태가 두 벌이 된다

**옛 저장소에는 넷째가 있었다.** `ColorNamer.cs`가 `De`라는 자기 별칭을 둬서 표식(`IsGerman`)에 안 잡히고 104곳이 한국어 없이 영어로 나가던 것이다. 여기서는 없다 — `scanner.MARKERS`가 `De`를 갖고 있어서 조립이 그 104곳을 이미 열었다. 그래서 3번 규칙이 표식 목록을 통째로 가져다 쓴다.

표식을 가져다 쓰면서 **낱말 경계 판정이 새로 필요해졌다.** `IsGerman`은 이름이 길어 남의 이름 안에 안 들어갔는데 `De`는 두 글자라 `Destination`의 머리에 그대로 있다. 부분 문자열로 재면 그런 문장에 앉은 리터럴이 통째로 조용히 빠지므로, `scanner._standalone`과 같은 판정을 정규식으로 둔다.

## 골든이 판단을 담는다

셋으로 안 갈리는 잔여분을 `golden/speech-sites.json`에 고정하고, 늘면 실패시킨다.

**골든에 넣는 것은 판단이라 `why`가 비어 있으면 검사가 빨개진다.** 다음 사람이 그 줄을 근거 없이 믿는 것을 막는다. `--write`는 기존 `why`를 그대로 옮겨 적고 새 자리만 빈칸으로 남기므로, 갱신 한 번에 사람이 쓴 판단이 날아가지 않는다.

빨개지면 셋 중 하나고, 어느 쪽인지는 사람이 정한다.

- 발화에 외국어가 새기 시작했다 → 고친다
- 통과시킬 자리가 새로 생겼다 → `--write`로 갱신하고 **`why`를 채운다**
- 그 자리가 없어졌다 → `--write`로 갱신한다

골든에는 **통과시킬 것과 아직 못 고친 결함이 같이 산다.** 어느 쪽인지는 `why`가 말한다.

## 한계

- **튜플 사전 두 파일은 범위 밖이다**(`OUT_OF_SCOPE`). `tools/assemble`이 `TUPLE_TABLES`로 건수만 세는 자리라, 여기서 다시 세면 상태가 두 벌이 되고 골든이 안 읽힌다. 목록을 베끼지 않고 그쪽 것을 가져다 쓴다
- **움라우트가 없는 독일어는 `sibling` 갈래로만 잡힌다.** `Ort`처럼 형제가 없는 자리에 홀로 앉아 있으면 못 본다
- **축자 문자열(`@"..."`)은 못 읽는다.** `tools/assemble`의 `scanner.read_literal`과 같은 한계다
- **`Installer/`와 `Launcher/`는 안 본다.** 그쪽은 자체 사전을 쓰고 `tools/loc-check`가 따로 본다
