# 손으로 옮긴 37곳 (끝남)

- 조사: 2026-08-18 / 옮김: 2026-08-18 / 업스트림 v5.88에서 한 곳 늘어남: 2026-08-18 / v5.92에서 또 한 곳: 2026-08-25

**원본은 파일이 아니라 커밋이다.** 손으로 옮긴 자리는 vendor의 `kr-port` 브랜치에서 제목에 `lines the generator cannot reach`가 든 커밋이 갖는다. 예전에 있던 `overlay/patches/0009`는 패치 파일을 없애면서 같이 사라졌다([vendor.md](../upstream/vendor.md)). 도구도 그 커밋을 읽는다 — `tools/ko-words`의 `hand_commits`가 브랜치에서 제목으로 찾아 `git show`의 더해진 줄을 센다.

**커밋은 하나가 아니다.** 업스트림이 생성기가 못 읽는 문장을 더할 때마다 하나씩 는다. v5.92의 `WalkMeshEndsBelowOrAbove`가 두 번째였고, 그때 도구가 제일 새 커밋 하나만 읽고 있어서 앞선 36곳이 통째로 검사 밖으로 빠졌다(2026-08-25, 현황판 §5-33).

문장 스냅샷은 `IsGerman ? "독일어" : "영어"` 모양만 읽는다. 여기 있는 것은 그 모양이 아니라서 **아무 보호도 못 받는다.** 조용히 빠뜨리기 제일 쉬운 자리다.

## 숫자가 셋이라 먼저 갈라 둔다

같은 것을 세 군데서 다르게 센다. 헷갈리면 여기를 본다.

| 수 | 무엇 | 어디서 나오나 |
|----|------|---------------|
| **43** | 스냅샷 파서가 못 읽은 자리 | `tools/strings-golden/golden/de-en.json`의 `unparsed` |
| **42** | 그중 진짜 손으로 볼 자리 | 아래 유형별 표의 합. 43에서 하나를 뺀 것은 `Pick(de, en, ko)` **헬퍼 선언 자체**라 문장이 아니다 |
| **37** | 실제로 한국어를 넣은 자리 | 손 케이스 커밋들이 더한 줄의 `IsKorean` 개수. 42에서 **데이터 표 참조 5곳**을 뺀 것이고, 그 5곳은 W-12(캐릭터 생성)다 |

`tools/docs-check`가 이 셋을 산출물과 대조한다. 손으로 고치면 빨개진다.

**전부 옮겼다**(37곳). 아래는 유형별로 무엇을 조심했는지의 기록이고, 업스트림이 새 문장을 더하면 같은 유형이 다시 생기므로 남겨 둔다.

**실제로 그렇게 됐다. 두 번.** 업스트림 v5.88이 `ConfigPageWithCount`를 더하면서 단수/복수 분기가 하나 늘었고, v5.92가 `WalkMeshEndsBelowOrAbove`를 더하면서 중첩 삼항이 하나 늘었다 — 이 표의 세 숫자가 그때마다 하나씩 올라간 이유다. 이런 자리는 골든 쌍이 그대로일 수 있어 **스냅샷이 아무 말도 안 한다.** `unparsed`가 오르는 것만이 신호이므로, 동기화 뒤에는 쌍 수뿐 아니라 이 값도 본다.

**옮긴 방식은 한국어 갈래를 앞에 덧대는 것이다** — `Loc.IsKorean ? <한국어> : IsGerman ? <독일어> : <영어>`. 독일어·영어 원문이 한 자도 안 바뀌므로 스냅샷이 그대로다.

**줄 번호는 여기 적지 않는다.** 이번 세션에도 한 줄 추가로 전부 밀렸다. 지금 목록과 번호는 이 명령이 그때그때 찍는다.

uv run --no-project python tools/strings-golden/strings_golden.py --write

## 유형별로 조심할 것

### 단수/복수 분기 7곳 — 옮기지 말고 지워라

```csharp
IsGerman ? (n == 1 ? "1 Materia-Slot" : $"{n} Materia-Slots")
         : (n == 1 ? "1 materia slot" : $"{n} materia slots");
```

한국어에는 단수·복수 문법이 없다. `마테리아 {n}칸` 하나면 끝이고 **안쪽 갈림길이 통째로 사라진다.** 독일어·영어 쪽은 그대로 둬야 하므로, 한국어만 갈림길 없는 형태가 된다.

**용어를 하나 틀리게 적어 뒀었다.** 여기 "머티리어"라고 썼는데 게임 표기는 **마테리아**다(Addon 481). 게임은 "머티리어"를 어디에도 안 쓴다 — `tools/ko-terms`로 확인했다.

여기 해당하는 것: 키 충돌 개수, 아이템 개수, 클래스 목록, 마테리아 칸, 전리품 수량 두 곳, 그리고 **설정 페이지의 설정 개수**(v5.88에 들어왔다).

예외 하나 — 전리품 쪽은 `count > 1`일 때만 수량을 **덧붙이고** 아니면 아예 안 말한다. 한국어에서 "1개"를 말할지 말지는 지워서 될 일이 아니라 정해야 한다.

**v5.88의 `ConfigPageWithCount`가 이 유형의 최근 예다.** 시스템 설정 창에서 탭을 옮기면 그 페이지에 설정이 몇 개인지 같이 말해 준다. 독일어·영어는 낱말이 단복수로 갈리지만(`Einstellung`/`Einstellungen`, `setting`/`settings`) 한국어는 `설정 {count}개` 하나다. `설정`은 게임 낱말이고(Addon 4000 `시스템 설정`), `개`는 이미 손 케이스 안에서 쓰던 세는 말이다(`항목 {count}개`, `키 충돌 {count}개`).

### 데이터 표 참조 5곳 — 여기는 손대는 자리가 아니다

```csharp
=> (Loc.IsGerman ? t.De : t.En)
```

문장이 이 줄에 없다. `(De, En, BriefDe, BriefEn)` 튜플 표에 있고, 그 표가 **3,023건**이다. 한국어를 넣으려면 이 삼항이 아니라 **튜플 모양 자체**를 바꿔야 한다.

**W-06에서 안 건드렸다.** 이건 W-12다. 순서상 캐릭터 생성이 마지막이고, 그때까지 앞의 것으로 방식이 굳는다.

`CharaMakeShapeText.cs`는 자동 생성물이라 파일을 고치면 안 된다 — `vendor/ff14-accessibility/tools/icons/shapes.tsv`에 열을 붙여 다시 만든다. 그 TSV는 업스트림 `cmdump shapedump`가 내는 것이라 클론에 없다.

### 조건이 밖에서 한 번 더 갈리는 4곳 — 자리가 4개다

```csharp
worlds.Count > 0
    ? (IsGerman ? "…월드 있음 독일어…" : "…월드 있음 영어…")
    : (IsGerman ? "…월드 없음 독일어…" : "…월드 없음 영어…")
```

한 곳만 채우고 넘어가기 쉽다. **네 자리 다 채웠는지 세고 넘어가라.**

### 중첩 삼항 17곳 — 한국어는 삽입 위치가 다르다

```csharp
$"{option}, {index} von {count}{(selected ? ", ausgewählt" : "")}"
```

독일어·영어는 끼워 넣는 조각이 문장 끝에 붙는데, **한국어는 어순이 달라 끝이 아닐 수 있다.** `{index} of {count}`가 "{count}개 중 {index}번째"로 뒤집히면 뒤에 붙던 ", 선택됨"의 자리도 같이 움직인다.

`{name}{(location != null ? ", on {location}" : "")}` 같은 것은 **조사**가 걸린다. 독일어 전치사 자리에 한국어 조사가 그대로 오지 않는다.

**v5.92의 `WalkMeshEndsBelowOrAbove`가 이 유형의 최근 예다.** 걸어갈 길이 끝났는데 남은 거리가 주로 수직일 때 그것을 말해 준다. 보간 안에 삼항이 넷이고(위·아래를 두 번씩), 게다가 표현식이 아니라 **메서드 본문**이라 파서가 두 번 막힌다. 한국어는 `그중 4미터 위. 목적지가 위쪽에 있음.`처럼 마침표로 가른다 — 원문이 하이픈으로 두 문장을 잇는 자리다.

### 문자열 이어붙이기 4곳 — 조각을 세라

제일 큰 것이 `/acc help` 전체 안내(73줄)다. **조각을 하나 빠뜨려도 컴파일도 되고 티도 안 난다.** 조각 수를 옮기기 전후로 세서 맞춰라.

### 다른 상수 참조 2곳 — 방위 배열

`CompassWords`(북·북동·…)와 `CompassAdjectives`는 값이 딴 데 있다. **8개짜리 배열이고 순서가 곧 의미다**(0=북 … 7=북서). 어긋나면 컴파일은 되고 엉뚱한 방향을 말한다.

한국어는 명사형·부사형 방위를 굳이 나누지 않아도 되는 경우가 많아 두 배열이 같아질 수 있다. **그래도 두 개로 둬라** — 하나로 합치면 독일어·영어가 깨진다.

### 배열 1곳

`RewardCurrencyLabels`가 `{ "Erfahrung", "Gil" }`. 인덱스로 꺼내 쓰므로 **개수와 순서를 그대로** 맞춘다.

### 스냅샷 안에 있는데도 위험한 것 — 세는 말 하나

`CounterConnector`는 평범한 삼항이라 스냅샷이 지킨다. **그런데 이건 말하는 쪽과 읽는 쪽이 같이 쓴다.**

```csharp
public static string CounterConnector => IsGerman ? "von" : "of";
public static string Counter(int index, int count) => $"{index} {CounterConnector} {count}";
```

`UIReaderService.TryParseSpokenProgress`가 자기가 찍은 이 문장을 **다시 읽어서** 사냥수첩 줄을 알아본다. 조건이 딱 셋이다 — 공백으로 끊어 **조각 3개**, 첫째와 셋째가 **전부 숫자**, 둘째가 `CounterConnector`와 **글자까지 같을 것**.

**한국어로 옮길 때 여기가 조용히 깨진다.** 자연스러운 한국어는 어순이 뒤집히고(`10개 중 3개`) 숫자에 단위가 붙는다. 그러면 첫 조각이 `3개`라 "전부 숫자"에서 떨어지고, **사냥수첩 목록이 통째로 사라진다.** 예외도 로그도 없다.

업스트림도 같은 자리에서 한 번 당했다 — 읽는 쪽에 `"von"`을 박아 놨더니 영어에서 사냥수첩이 사라졌고, 그래서 상수를 노출한 것이다(`AccessibilityStrings.cs`의 주석이 그 사고를 적어 뒀다).

옮길 때 지킬 것: **연결어 한 낱말만 바꾸고, 어순과 숫자 자리는 건드리지 않는다.** 어순을 바꾸려면 읽는 쪽(`TryParseSpokenProgress`)을 같이 고쳐야 하고, 그건 번역이 아니라 코드 변경이다.

### 기타 2곳

**버전 안내** — `version.Replace(".", " Punkt ")`. 소수점을 말로 읽는다. `5 점 87`로 나가고, **이대로 두기로 정해졌다**(2026-08-18, 현황판 §3 D-4).

**속성 보정값** — `AttributeValue`는 **독일어와 영어 분기가 글자까지 똑같다.**

```csharp
IsGerman
    ? $"{name} {(v < 0 ? "minus" : "plus")} {Math.Abs(v)}"
    : $"{name} {(v < 0 ? "minus" : "plus")} {Math.Abs(v)}";
```

minus/plus가 두 언어에서 같은 말이라 그렇게 됐다. 한국어는 `마이너스`/`플러스`로 넣었다.

**한때 "업스트림에 보내 지우자"고 적어 뒀는데 기각됐다.** 같은 모양 15곳을 전부 뽑아 보니 **13곳이 이미 한국어를 다르게 갖고 있었다** — 죽은 갈림길이 아니라 세 번째 언어가 정확히 쓰는 자리다. 지웠으면 프랑스어·일본어의 자리까지 같이 닫는 것이었다. 근거는 [patches/rejected.md](../../patches/rejected.md).
