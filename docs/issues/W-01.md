# W-01 준비 판정이 낡은 후크 폴더를 가리킨다

**상태**: 열림
**증상**: `--check`의 `dalamud ready` 줄이 달라무드가 실제로 쓰는 폴더가 아니라 옛 폴더를 지목한다.

## 무엇이 일어나나

2026-09-10 실측이다. 후크 폴더가 둘 있는 머신에서 이렇게 나온다.

    [OK ] dalamud ready        C:\Users\advck\AppData\Roaming\XIVLauncherKR\addon\Hooks\15.0.3.2

그런데 실제로 적재되는 것은 **15.0.3.3**이다. 업데이터 설정의 `HookVersion`이 `15.0.3.3`이고 게임에도 그것이 주입된다. 둘 다 한국 패치 마커를 갖고 있어서 어느 쪽이든 "준비됨"으로 읽히는데, 화면에 뜨는 이름은 **안 쓰이는 쪽**이다.

준비 여부 자체는 맞다. **틀리는 것은 지목하는 이름이다.**

## 왜 그런가

`kr/Installer/KrProfile.cs:309` `KrPatchedHookFolder()`가 `addon\Hooks` 밑을 열거해 **마커 파일이 있는 첫 폴더에서 멈춘다.** 어느 것이 실제로 쓰이는지는 안 본다.

    foreach (var version in Directory.EnumerateDirectories(hooks))
    {
        if (Directory.EnumerateFiles(version, KrPatchMarker).Any()) return version;
    }

`15.0.3.2`가 `15.0.3.3`보다 먼저 열거되어 그것이 나온다. 열거 순서 자체가 보장된 것은 아니지만, 실측에서 이 머신은 그렇게 나왔다.

**마커 이름을 패턴으로 두는 것은 의도다.** 같은 파일의 주석이 까닭을 적고 있다 — 이름과 개수를 박으면 다음 업데이터 버전에서 영구 타임아웃이 된다. 그러니 **패턴을 좁히는 방향으로 고치면 안 된다.** 고를 기준을 더해야 한다.

## 딸린 것

`DalamudMissingPiece()`와 `DalamudInstalled`가 같은 함수를 쓴다. 준비 여부는 "하나라도 있으면 참"이라 결과가 바뀌지 않지만, 15분 대기가 실패했을 때 `KrDalamudWaitMissing`이 대는 경로도 같은 자리에서 온다.

## 닫히는 조건

후크 폴더가 둘 이상인 머신에서 `--check`의 `dalamud ready`가 **업데이터 설정의 `HookVersion`과 같은 폴더**를 지목하는 것을 확인한다. `HookVersion`이 없거나 그 폴더가 없으면 가장 새 것을 고른다.
