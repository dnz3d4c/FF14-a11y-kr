# 릴리스 노트 검사 규칙 N1~N26

릴리스 노트 검사기가 볼 것의 명세다. **재포팅 시점에 이 검사기는 아직 없다.** 만들 때 이 문서가 입력이 되고, 만든 뒤에는 검사기가 `--rules`로 이 목록을 출력하게 해서 두 벌이 되지 않게 한다.

문체와 판정 기준은 `ko-release-notes` 스킬이 갖는다. 여기 있는 것은 기계가 재는 것뿐이다.

| 코드 | 무엇을 보나 |
|------|-------------|
| N1 | BOM 없는 UTF-8이다. BOM이 붙으면 첫 줄이 제목이 아니라 본문 글자가 된다 |
| N2 | `##` 제목이 없고 첫 줄이 `### 설치`다. 릴리스 페이지 제목과 같은 정보를 본문에 두지 않는다 |
| N3 | `###` 절이 정해진 목록과 순서까지 같다. 모르는 절은 통과가 아니라 위반이다 |
| N4 | 제목이 `###` 일곱뿐이다. 절 목록이 일곱인데 이 규칙이 여섯이라고 적힌 채로 이관됐다 — 미검증 절을 나중에 더하면서 이 숫자를 안 고친 것이다. 검사기를 만들 때 절 목록에서 개수를 계산하고 여기에 숫자를 적지 않는다 |
| N5 | 본문의 판 번호가 전부 이번 판이다. 지난 판을 복사해 한 자리를 안 고치는 것을 막는다 |
| N6 | 본의 자리표시자가 안 남았다 |
| N7 | 변경 항목이 커밋 트레일러 규칙과 같다. 같은 문자열이라 검사기를 그대로 부른다 |
| N8 | `모드 변경사항:` 줄이 정확히 하나이고, 그 줄 위나 아래에 변경 항목이 있다 |
| N9 | 인라인 링크가 없다 |
| N10 | 항목을 통째로 강조하지 않았다 |
| N11 | 절당 굵게 하나까지고 기울임은 안 쓴다 |
| N12 | 백틱 안 한글은 배포물 파일 이름 둘뿐이다 |
| N13 | **산문 절의** 말투가 습니다체다. 변경 항목은 반대로 명사형이라(N7) 이 검사가 안 본다 |
| N14 | 사용자 화면에 안 뜨는 내부 이름이 없다. `※` 줄의 `Dalamud`만 예외다 |
| N15 | 맨 끝 줄이 `※`로 시작하는 자산 안내 하나다 |
| N16 | 목록 절이 제목 바로 아래에서 목록으로 시작한다. 변경사항 절만 `모드 변경사항:` 줄로 시작해도 된다 |
| N17 | 항목 안에 목록 표지가 다시 나오지 않는다. 항목 둘이 한 줄로 붙은 것을 잡는다 |
| N18 | 노트에 쓰면 안 되는 낱말이 없다. 목록은 `korean/lexicon.json`의 `note` 대상이고 대체어와 근거를 같이 돌려준다 |
| N19 | `한국어 번역 문장 수정:` 줄이 있으면 하나뿐이고, 값이 비어 있고, `모드 변경사항:` 줄보다 앞이고, 아래에 목록이 있다 |
| N20 | 릴리스에서 걷어낸 자산을 백틱 안에서 지목하지 않는다 |
| N21 | 우리 변경 항목 수가 원본의 절 수보다 적지 않다. 원본 노트에서 절을 하나도 못 찾은 것도 여기다 |
| N22 | 원본이 실제 발화를 인용해 보여 준 자리를 목록으로 되묻는다 |
| N23 | 원본 절 목록을 판마다 되묻는다. 각 절이 우리 노트 어디에 있는지 짚는 자리다 |
| N24 | 변경 항목이 모드의 발화를 `알려 줌`·`말함`·`들림`으로 서술하지 않는다. 인용하는 `~라고 말함`은 통과하고, 산문 절은 안 본다 |
| N25 | 변경사항 절의 목록 사이에 표지가 둘(`한국어 번역 문장 수정:`·`모드 변경사항:`)뿐이다. 마지막 항목 뒤의 꼬리 문단은 안 본다 |
| N26 | 미검증 절이 `밝히-`로 어구를 지어내지 않는다. 종결형 전체는 안 본다 |

## 규칙 사이에 난 구멍

**N24와 N25는 규칙이 이미 문서에 있었는데 기계가 안 봐서 다섯 판 연속 새어 나간 자리다.** N25가 잡는 세 번째 표지 줄을 N8도 N19도 N16도 안 봤다. 셋 다 자기 표지가 몇 개고 어디 있는지만 세지, 규칙 밖 표지가 하나 더 생긴 것은 세는 자리가 없었다.

검사기를 만들 때 같은 형태의 구멍을 만들지 않으려면, 개수를 세는 규칙마다 **"내가 안 세는 것이 통과하는가"**를 같이 본다.

## 원본 노트를 같이 받아야 도는 것 셋

N21·N22·N23은 우리 노트만으로는 못 잰다. 우리 판 번호의 앞 두 마디로 원본 태그를 만들어 노트를 받아 넘긴다.

**못 받으면 건너뛴 것을 화면에 남긴다.** 원본을 안 본 판과 다 옮긴 판이 같아 보이면 안 된다.

**N23은 개수와 무관하게 판마다 뜬다.** 개수만으로는 절 누락을 못 잡기 때문이다. 원본 정보 단위가 10인데 우리 항목이 14개인 판이 있었고, 도구 절을 통째로 빼도 13이라 개수 검사를 그냥 통과했다.

절 목록과 발화 목록을 다 짚었으면 사람이 선언해서 넘긴다. **N21은 그 선언으로 못 넘긴다** — 개수 미달은 사람이 봤다고 사라지는 사실이 아니다.

## N7이 한 번 뒤집힌 자리

`삭제.`·`유지.`는 마지막 음절의 종성이 `ㅁ`이 아니고 `출력함 .`은 마침표 앞에 공백이 있어서, 명사형 판정이 셋 다 아니라고 봤다. **N7이 거르려던 것은 제목의 `~한다`체와 존댓말이고 받침 없는 서술성 명사는 그 대상이 아니다** — 규칙이 목적보다 좁았다.

그래서 명사형을 열거하는 대신 **종결어미(`다`·`요`·`죠`·`까`·`네`)만 막고** 마침표 앞 공백은 무시한다.

## 언제 도나

발행 직전 한 번만 돌리면 늦다. 노트가 여러 커밋에 걸쳐 고쳐지는 동안 한 번도 안 도는 판이 실제로 있었다. **이번 판 노트를 스테이징하면 커밋 훅에서도 돈다.**

훅은 **이번 판 하나만** 본다. 나가 있는 판은 소급해 고치지 않으므로, 옛 판을 고치는 커밋이 막히면 안 된다.
