# 발행

배포물을 짓고 릴리스로 내보내는 절차다. 노트를 어떻게 쓰는지는 [release-notes-rules.md](release-notes-rules.md)와 `ko-release-notes` 스킬이 갖는다.

## 자산 넷이 한 릴리스에 같이 올라간다

사용자가 새 판을 받는 길이 둘이고 둘 다 이 릴리스의 자산을 가리킨다.

| 자산 | 누가 받나 |
|------|-----------|
| `FF14AccessibilityInstaller-KR.exe` | **사람.** 설치 프로그램 자기 갱신도 이것을 받는다 |
| `FF14Accessibility.zip` | 달라무드, 그리고 모드의 새 버전 확인 |
| `repo.json` | 달라무드 커스텀 저장소 |
| `installer.json` | 설치 프로그램 자기 갱신 (버전과 SHA-256) |

**하나라도 빠지면 받는 쪽은 오류가 아니라 "새 판이 없다"로 읽는다.** 그래서 올리고 끝내지 않고 도로 받아 잰다.

## 버전은 네 마디이고 넷째가 한국어판 몫이다

값을 어디서 읽고 언제 되돌리는지는 [assemble.md](assemble.md)의 「버전 찍기」가 갖는다. 여기는 발행 쪽에서 걸리는 것만 적는다.

**앞 세 마디가 같은 채로 다시 내면 갱신이 침묵으로 선다.** 설치 프로그램의 `IsNewer`도 달라무드도 버전만 보므로 오류가 안 나고, 내는 사람 화면에도 안 남는다. 그래서 자산을 올리기 직전에 `--check-bump`가 막는다.

**원본 핀을 옮기면 한국어판 개정은 `0`으로 되돌린다.** 앞 마디가 올라가므로 단조 증가가 안 깨진다. `release.py`의 `upstream_unchanged`가 앞 세 마디로 그 판정을 하고, 핀이 안 움직인 개정판에는 원본 절 커버리지 검사를 면제한다 — 옮길 원본 절이 없는 판이기 때문이다.

## 게이트가 여섯이고 `gh`는 맨 뒤다

`gh`를 부르고 나면 바깥에 흔적이 남고 되돌리는 길이 없다. 그래서 판정이 전부 그 앞이다.

1. 노트 원본을 `dist/release`로 옮긴다
2. **소스가 커밋되어 있나** — 커밋 안 된 트리로 만든 물건이 나가는 것을 막는다
3. **게임에 없는 낱말을 쓰나** — `ko_words --require-dump`
4. **사람이 노트 본문을 봤나** — `FF14_NOTES_APPROVED`
5. **노트가 규칙에 맞나** — 원본 노트를 받아 커버리지까지 잰다
6. 릴리스를 내거나 덮어쓴다

## 사람이 거는 탈출구

이름을 바꾸지 않는다. 손으로 거는 값이라 이름이 갈리면 문서와 손버릇이 같이 낡는다.

| 변수 | 무엇을 선언하나 |
|------|-----------------|
| `FF14_NOTES_APPROVED` | 노트 본문을 사용자에게 보이고 승인받았다 |
| `FF14_NOTES_ACKED` | 원본 절을 우리 노트 어디에서 다뤘는지 짚었다 (N23) |
| `FF14_WORDS_CHECKED` | 낱말 대조를 개발 머신에서 통과시켰다 |
| `FF14_E2E_CHECKED` | 설치 실증을 개발 머신에서 통과시켰다 (`pack.py`) |
| `FF14_UPSTREAM_NOTES_UNREACHABLE` | 원본 노트를 정말 못 받는 상태다 |
| `FF14_RELEASE_SAME_VERSION` | 같은 판을 그대로 다시 올린다 |

**넘어간 것은 전부 화면에 남는다.** 조용히 지나가면 잰 판과 안 잰 판이 같아 보이고, 그러면 게이트가 있으나 마나다.

## 두 길 — 로컬과 CI

### 로컬

    uv run python tools/pack/pack.py
    uv run python tools/pack/release.py --dry-run
    uv run python tools/pack/release.py

`--dry-run`은 **바깥을 하나도 안 부른다.** 무엇을 하려는지 먼저 찍어 본다.

### CI

[`.github/workflows/release.yml`](../../.github/workflows/release.yml)을 손으로 부른다. 태그 푸시로 안 건다 — 실수 한 번이 그대로 나가는 트리거는 두지 않는다.

**기본 가지에서만 돈다.** 손으로 부르는 워크플로는 어느 가지에서든 부를 수 있고 발행 잡이 그 가지의 도구를 쓰기 토큰으로 돌리므로, 막지 않으면 머지 안 된 코드가 릴리스를 낼 수 있다.

**같은 태그를 겹쳐 올리지 않는다.** 덮어쓰기 갈래가 자산을 그대로 갈아 끼우므로, 한 실행이 되받아 재고 끝난 뒤 다른 실행이 다시 덮을 수 있다.

#### 러너가 못 재는 것 셋

입력으로 선언하고, 잡 요약이 그 셋을 이름으로 적는다. **초록을 "다 쟀다"로 읽으면 안 된다.**

| 게이트 | 왜 못 재나 |
|--------|-----------|
| 낱말 대조 | 게임 텍스트 덤프를 읽는다. 재배포하지 않기로 한 데이터라 러너에 영영 없다 |
| 설치 실증 | 설치 프로그램을 버리는 프로필에 대고 실제로 돌리는데, 그 안에 플레이 바로가기를 만드는 단계가 있고 러너에는 게임이 없다 |
| 노트 승인 | 사람이 본문을 읽고 판단하는 일이다 |

#### 권한을 가르는 기준은 받느냐가 아니라 실행하느냐다

짓는 잡은 원본 csproj의 커스텀 MSBuild 타깃을 돌리므로 **원본이 쓴 코드를 실행한다.** 그래서 읽기 권한만 갖는다. 올리는 잡은 쓰기 권한을 갖되 `dotnet`을 아예 안 부른다 — 서브모듈은 받는다. 소스 게이트가 원본 기록을 봐야 하고, 파일로 있는 것은 아무 일도 하지 않는다.

## 올린 것을 도로 받아 잰다

    uv run python tools/release-manifest/release_manifest.py --release <태그>

**이 단계를 건너뛰지 않는다.** 발행 도구는 올리고 끝나지 자산이 제대로 올라갔는지 다시 보지 않는다. 업로드가 반만 돼도 `gh`는 0으로 끝나고, 받는 쪽에는 오류가 아니라 "새 판이 없다"로 보인다. 압축 안의 매니페스트와 EXE의 PE 버전 자원을 직접 읽어 값을 다시 계산한다.

## 참조 릴리스는 `--prerelease`로 만든다
