# 릴리스 노트

**파일 하나가 판 하나다.** 이름은 `<네 마디 버전>.md`이고 `5.95.0.0.md`처럼 적는다. 발행할 때 이 파일을 그대로 릴리스 본문으로 올린다.

## 왜 저장소가 갖나

기존 저장소는 노트를 `dist/release/`에 손으로 쓰고 그대로 올렸는데, `dist/`가 `.gitignore`에 있어서 **본문이 판마다 사라졌다.** `git log --all -- '*release-notes*'`가 0건이었다. 다음 판을 쓸 때 이전 판을 볼 수 없으니 매번 새로 지어냈고, 그래서 `v5.88.0.0`과 `v5.88.0.1`의 절 이름과 종결형이 이미 서로 달랐다.

여기 두면 이전 판이 옆에 있다. 새 노트를 쓸 때 먼저 여는 것이 그 파일이다.

## 무엇이 이 파일을 판정하나

- **기계가 재는 것**: `docs/dev/release-notes-rules.md`의 N1~N26. 검사기가 그 목록을 `--rules`로 내므로 명세가 두 벌이 되지 않는다.
- **사람이 재는 것**: `ko-release-notes` 스킬. 문체와 절 구성과 발행 전 승인 절차를 그쪽이 갖는다.

## 지우지 않는다

`docs/issues/`와 반대다. 결함은 닫히면 지우지만 노트는 그 판이 무엇을 냈는지의 기록이라 남는다.
