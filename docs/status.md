**판정은 잔량으로 한다.** "몇 행 반영"이 아니라 **영어로 나가는 자리가 몇 곳인가**를 본다. 지금은 4 + 10 + 3,023이다.

**여덟 판이 더한 문장을 전부 옮겼고 잔량이 얹기 전으로 돌아갔다.** 얹은 직후에는 미적용이 66곳, 못 읽음이 12곳이었다. 못 읽음 둘을 먼저 편 뒤 미적용이 74곳으로 늘었는데, 그것이 옳은 방향이다 — 적 색상 여덟이 파서 밖에서 안으로 들어온 것이다.

`Masked Carnivale`은 **게임 한국어 이름을 못 찾아 원어로 뒀다.** Addon 시트에 `가면`이 8건 있는데 콘텐츠 이름은 하나도 없다. 지어내지 않는다 — 이름을 확인하면 대장 한 줄로 바뀐다.

캐릭터 생성의 색상 낱말 96개는 **아직 귀 판정을 안 받았다.** 게임에 색상 이름이 없어서 모드가 짓는 말이고, 방위 낱말은 차례가 어긋나도 컴파일되고 어느 검사도 안 걸린다. 둘 다 인게임에서 들어야 한다.

### 깔고 재는 법

    uv run python tools/pack/pack.py
    dist\FF14AccessibilityInstaller-KR.exe --install --skip-vnavmesh

**개발용 자리에 깔지 않는다.** 정식 자리와 상호 배타적이라 같은 모드가 두 번 적재되고, 무엇보다 들리는 것과 낸 것이 갈라져 귀 판정이 무효가 된다. `--install`은 릴리스를 타지 않고 EXE 옆의 zip을 쓰므로 방금 만든 것이 그대로 깔린다.

깐 뒤에 잰다 — 설치본 DLL의 해시가 `dist/FF14Accessibility.zip` 안의 것과 같은지, `devPlugins`에 우리 것이 없는지, 매니페스트의 `InstalledFromUrl`이 새 저장소 주소인지. 게임이 떠 있으면 `Tolk.dll`을 잡고 있어서 반만 깔리므로 끈 상태에서 돌린다.

## CI에서만 드러난 결함 둘 — 기록해 둔다

로컬 실증과 교차 리뷰가 둘 다 지나쳤고 **실제로 푸시해야만** 나왔다.

- 트리거가 `branches: [main]`인데 기본 브랜치가 `master`라 워크플로가 아예 안 돌았다. 문법이 맞아 아무 검사도 안 걸렸다.
- 윈도 러너의 파이썬 stdout이 cp1252라 우리 도구가 한국어를 내는 순간 죽었다.

**2026-09-04에 넷이 더 나왔다.** 첫 PR과 첫 CI 발행이 각각 둘씩 데려왔다.

- 저장소 설정의 "Actions가 PR을 만들 수 있음"이 꺼져 있어 동기화가 밀기까지 하고 PR 생성에서만 죽었다. 옛 저장소 워크플로 주석이 경고해 둔 함정인데 그 설정이 새 저장소로 안 옮겨졌다.
- 워크플로 검사기가 PR 체크아웃에서 기본 가지를 "없는 브랜치"로 잡았다. 받아 오는 것이 병합 결과 ref 하나뿐이라 그렇다. 이 저장소는 master에 바로 커밋해 와서 PR이 없었고, 그래서 지금까지 안 드러났다.
- 배포 도구가 .NET SDK를 개발 머신의 스쿠프 경로로만 찾았다. 러너의 SDK는 액션이 깔아 PATH에 둔다.
- 설치 실증이 플레이 바로가기를 만드는데 러너에는 게임이 없다.

**공통점은 "저장소 밖 또는 러너 안의 사실"이라는 것이다.** 로컬에서 명령을 그대로 돌리는 실증으로는 원리적으로 안 잡힌다. 새 워크플로를 더할 때는 반드시 한 번 밀어 보고 결과를 확인한다. **뒤의 둘은 그 실증조차 한 번에 못 잡았다** — 발행을 네 번 돌리고서야 초록이 됐고, 매번 다음 단계에서 새 사실이 나왔다.
