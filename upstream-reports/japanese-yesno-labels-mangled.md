# 예/아니오 라벨의 일본어가 물음표로 깨져 있다

**상태**: 초안
**대상**: `FF14Accessibility/Services/UIReaderService.cs:505`의 `YesNoLabels` (v6.08.129)
**심각도**: 낮음. 질문 칸(`PromptText`)이 빈 일본어 확인 대화 상자에서만 생긴다

## 증상

v6.08.129의 `YesNoLabels`가 이렇다. v5.95부터 그대로다.

    ["Ja", "Nein", "Yes", "No", "??", "???", "Oui", "Non"]

독일어·영어·프랑스어 라벨은 멀쩡한데 일본어 자리 둘만 물음표다.

## 인코딩 손상이다

**문자 수가 정확히 맞는다.** `はい`가 2문자이고 `??`가 2문자, `いいえ`가 3문자이고 `???`가 3문자다. 어느 시점에 파일이 일본어를 표현하지 못하는 인코딩(cp1252 같은 것)을 거치면서 문자마다 물음표로 치환된 것이다.

터미널이 잘못 보여 준 것이 아니다. 파이썬으로 UTF-8로 읽어 `repr`로 찍어도 물음표다.

## 무엇이 망가지나

`YesNoLabels`를 쓰는 곳은 `ReadYesNoQuestion`(`:14053-14075`)의 두 줄(`:14063`, `:14071`)뿐이다. `PromptText`가 비었을 때 텍스트 노드에서 질문 문장을 고르면서 버튼 글자를 건너뛰는 거름망이다.

    if (!string.IsNullOrWhiteSpace(text) && text.Length > 2 && !YesNoLabels.Contains(text)) return text;

2자 이하는 길이 조건이 먼저 거르므로 `はい`는 영향이 없다. 3자인 `いいえ`만 거름망을 통과해, 질문 칸이 빈 일본어 대화 상자에서 질문 대신 "아니오" 버튼 글자를 질문으로 읽을 수 있다. 질문 칸이 비는 대화 상자가 실제로 얼마나 있는지는 확인하지 않았다.

`.cs` 파일 전체에서 물음표만으로 된 리터럴을 훑었더니 **이 한 곳뿐이다.** 손상이 퍼져 있는 것이 아니라 한 번의 사고로 보인다.

## 고칠 방향

두 값을 `"はい"`, `"いいえ"`로 되살린다. 그리고 그 파일이 앞으로 UTF-8로만 저장되게 한다 — 한 번 일어난 손상은 편집 도구나 빌드 절차가 그대로 있으면 다시 일어난다.

## 우리 쪽 사정

**같은 일이 한국어판에서도 생길 수 있다.** 한국어 버튼 `아니오`도 세 글자라 길이 조건을 통과하고, 배열에 한국어 라벨이 없다. 이 저장소에 그 배열을 고치는 덧대기는 없다 — 예전에 "더한다"고 적어 두었던 것은 사실이 아니었다(2026-10-18 대조). 질문 칸이 빈 대화 상자를 인게임에서 만난 기록이 없어서 아직 덧대지 않았다. 귀 판정에서 확인 대화 상자가 질문 대신 "아니오"를 말하면 한국어 라벨을 더하는 덧대기를 둔다.
