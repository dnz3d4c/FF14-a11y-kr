# 가루다 워프 보조가 같은 기술의 연속 시전에서 빠질 수 있다

**상태**: 초안. 아래 판정대로 **아직 안 보낸다** (기준 4의 앞 절반이 게임 사실 하나에 걸린다)
**대상**: `FF14Accessibility/Services/NocturneWarpService.cs:117`, `:141`, `:153` (v6.08.32, `f5cdf47`)
**심각도**: 발현되면 높음. 기본값이 `Auto`(`Configuration.cs:598`)라 워프가 조용히 빠진다

## 무엇이 소스로 확정되나

시전을 처리했는지 기억하는 키가 시전 한 번이 아니라 **시전자와 기술 종류**만 담는다.

```csharp
// NocturneWarpService.cs:117
var castKey = garuda.GameObjectId ^ ((ulong)castId << 32);
```

같은 가루다가 같은 기술을 다시 쓰면 키가 비트 단위로 같다. 순간 돌풍(`:141`)과 마녀의 회오리(`:153`)는 `_handledCastKey == castKey`면 그냥 return한다. 키가 0으로 돌아가는 곳은 `ResetDutyState`(`:159-165`) 하나이고, 부르는 곳은 구역 이탈(`:86`)과 워프 슬롯 없음(`:92`)뿐이다. 시전이 끝날 때(`:113`)도 가루다를 못 찾을 때(`:97`)도 키를 건드리지 않는다.

**막히는 순서**

- 같은 기술 처리 → 같은 기술. 두 번째가 막힌다.
- 같은 기술 처리 → 세 기술에 안 드는 다른 시전 → 같은 기술. 가운데 시전은 어느 분기에도 안 걸려 키를 덮어쓰지 않으므로 막힌다.
- 전멸 후 재도전. 가루다가 죽거나 사라지면 `:97`에서 return만 하므로, 마지막 처리 기술과 재도전 첫 기술이 같고 `GameObjectId`가 유지되면 막힌다.

**안 막히는 순서**

- 사이에 다른 기술이 처리되면 `:130`·`:146`·`:155`가 키를 덮어써서 풀린다. 그래서 "영구 차단"은 아니다.
- 앞 시전의 `TryAssist`가 실패했으면(`:260` 0.55초 제한, `:264` 대상 지정 거부) 키가 저장되지 않는다.

**삭풍의 비명은 무관하다.** `:122`의 `&& _mistralPhase != 0`은 절대 참이 안 된다. `_mistralPhase == 1`이면 `:100-110`이 먼저 return하므로 `:122`에 닿을 때 값은 늘 0이다. 삭풍의 비명의 중복은 키가 아니라 phase가 막는다. 이 죽은 가드는 동작에 영향이 없어 따로 보내지 않고 관찰로만 적는다.

## 고칠 방향에 대한 우리 판단

수정 코드는 붙이지 않는다. 어느 쪽으로 고칠지는 원본이 정한다. 다만 두 안을 따져 둔다.

- **시전이 끝날 때(`!IsCasting`) 키를 비우는 안은 권하지 않는다.** 두 시전 사이에 시전이 아닌 프레임이 있어야 하는데 그 보장이 없고, 시전 중 한 틱이라도 꺼지면 같은 시전에 다시 발동한다. `Auto`에서는 두 번째 `ExecuteDutyActionSlot`(`:284`), 곧 엉뚱한 워프가 된다.
- **진행률이 문턱 미만일 때 같은 키를 보면 비우는 안**은 새 시전이 진행률 0에서 시작한다는 것 하나에만 기댄다. 순간 돌풍은 문턱 0.88(`:40`)에 시전 17.3초(`game-api.md:1232`)라 약 15초의 창이 있어 소스와 시트로 닫힌다. 전멸 경로도 함께 닫는다. 마녀의 회오리는 시전 시간을 몰라 창의 길이를 모른다.

## 기준 다섯

1. **코드에 한국이 안 나온다.** 통과.
2. **다른 클라이언트에서도 고쳐진다.** 통과. 언어와 무관한 로직이다.
3. **원본의 결정을 뒤집지 않는다.** 통과. "한 번만 보조"로 정한 흔적이 없고, 같은 파일의 삭풍의 비명은 시전마다 보조한다.
4. **글섭 클라 없이 판정된다.** **앞 절반이 실패한다.** "반복되면 막힌다"는 소스로 확정되지만, 반복이 실제로 오는지는 게임 사실이고 우리는 잴 수 없다.
5. **명백한 기존 로직의 오류다.** 조건부. 반복이 온다는 전제가 서면 갈리지 않는다.
